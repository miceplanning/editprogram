# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Status

This is a static (no-build) HTML/CSS/vanilla-JS event landing site (Korean, mobile-first) for company workshop/tour events, e.g. "제주 드림투어". There is no Node/npm toolchain in this environment — do not assume `npm`/`npx` are available.

## Build/lint/test

None. There is no build step, package.json, linter, or test suite. Open `index.html` directly in a browser (or serve the folder statically) to preview; there is no single-test command because there are no tests.

## Architecture

- Pure static site: `index.html`, `schedule.html`, `upload.html`, `flight.html`, `location.html`, `faq.html`, `survey.html`, each loading `css/style.css` then `js/content.js` → `js/main.js` → a page-specific script (`home.js`/`schedule.js`/`upload.js`/`flight.js`/`location.js`/`faq.js`/`survey.js`) in that order.
- `js/content.js` is the single content data file (event name, date, notice banner, rain-plan, contact/staff, meeting info, `schedule[]`, `locations[]`, `checklist[]`, `faq[]`, `survey`, `flight`, `sectionsEnabled`) — the source of truth non-developers edit between events, either by hand or via `editor.html`. It's heavily commented in Korean.
- Multi-day events: each `schedule[]` item carries an optional `date` field, an ISO `YYYY-MM-DD` string from an `<input type="date">` in the editor (empty/omitted = single-day event, the default, unchanged behavior). `formatDateLabel(isoDate)` (defined in both `js/main.js` for the participant pages and duplicated standalone in `js/editor.js`, since `editor.html` doesn't load `main.js`) converts it to a Korean display label like `"7/2(목)"` computed from the real weekday — never store or expect that display format in `content.js` itself. `schedule.js`'s `scheduleContentHtml()` checks `schedule.some(i => i.date)` and, if any item has one, groups consecutive same-date items under a `.day-header`; it does not reorder items, so schedule order in `content.js` must already be date-grouped. `home.js`'s timeline preview also prefixes the formatted date when present. `findNextScheduleItem()` in `schedule.js` is date-aware when any item has `date` set: it compares against `todayIso()` (local calendar date) first for today's remaining items, then falls back to the earliest item on a future date — so the sticky "다음 일정" bar correctly skips ahead across days.
- Participant photo upload has no backend: each `schedule[]` item can carry `photoUpload: { enabled, formUrl, driveFolderUrl }`. `formUrl` is a Google Form (file-upload question) participants submit to; `driveFolderUrl` is the Drive folder those responses land in, embedded read-only via `https://drive.google.com/embeddedfolderview?id=...` (same no-API-key embed pattern as the Google Maps embed on the location page). `js/photo-upload.js` holds the shared helpers (`extractDriveFolderId`, `driveFolderEmbedUrl`, `hasAnyUploadSection`, `buildUploadCard`); `upload.html`/`js/upload.js` lists every enabled item, `schedule.js`'s accordion just links to `upload.html` instead of duplicating the widget, and `main.js`/`home.js` only show the "사진업로드" nav tab/quick-menu entry when `hasAnyUploadSection` is true.
- Flight-ticket lookup also has no backend: `content.js.flight = { formUrl, notice, records[] }`, where each `records[]` item is one participant's departure/return leg (`name`, `departure*`/`return*` fields for date/airline/time/location/flight number/reservation code). `flight.html`/`js/flight.js` renders a Google Form link plus a name-search box that filters `records[]` client-side (exact match first, substring fallback) so a participant only sees their own row — note the full roster still ships in the page source since this is a static site with no server-side filtering. `editor.html`'s "항공권 정보" panel lets an operator paste a tab-separated block copied straight out of Excel/Google Sheets (`parseFlightPasteText` in `js/editor.js` strips an optional leading NO./header row and an optional leading row-number column) in addition to editing/adding rows one at a time.
- `sectionsEnabled` (rainPlan/staff/meetingSummary/checklist/faq/survey/flight) lets an operator hide a whole optional section for one event without deleting its data — `home.js` checks it before rendering each block, and `main.js` filters the FAQ/survey/flight nav tabs by it. `flight` defaults to `false` (opt-in) since it's event-specific, unlike the other sections which default to `true`.
- `js/main.js` renders shared chrome on every page (notice banner, sticky header, floating call-now button, bottom tab nav) based on `document.body.dataset.page`.
- Each page's own script renders its `<div id="*-content">` from `window.CONTENT` using small HTML-string builder functions (`escapeHtml`, `telHref`, `mapButtonHtml` are shared helpers defined in `main.js`).
- `editor.html` + `js/editor.js` + `css/editor.css` are an operator-only, no-backend form editor: it loads `js/content.js` into `window.CONTENT`, deep-clones it into a local `state` object, lets you edit/add/remove/reorder every field through form controls (each dynamic list row binds inputs directly to the object reference in `state`, so re-render only happens on add/remove/move — not on every keystroke), and on "저장" serializes `state` back into a `window.CONTENT = {...}` file via `Blob`/`URL.createObjectURL` for the operator to download and overwrite `js/content.js` with. It is not linked from the visitor-facing nav and has no auth — treat it as unlisted, not private.
- `projects.html` + `js/projects.js` + `js/project-store.js` layer optional multi-draft management on top of the editor via `localStorage` (browser-local only, never deployed data): each draft is `dreamtour_project_<id>` plus an index at `dreamtour_project_index`. Opening `editor.html?project=<id>` makes `editor.js` read `PROJECT_ID` from the query string, seed `state` from that stored draft instead of `window.CONTENT`, and debounce-autosave every edit back to `localStorage` via `markDirty()`. Opening `editor.html` with no `project` param keeps the original single-project behavior (seeds from `window.CONTENT`, no autosave, "unsaved changes" warning on unload). Either way, `content.js` 파일 저장 is still required to actually ship a draft to the live site.
- No frameworks, bundler, or npm dependencies — everything runs directly in the browser via `<script src>` tags.
- Deploy target is static hosting (Vercel "Other" framework preset, or GitHub Pages) — see [README.md](README.md) for the operator-facing editing/deploy guide.

## Multi-event archive

- Past and in-progress events live permanently under `<org-slug>/<event-slug>/` (English slugs, e.g. `dreamtower-workshop/31st-dreamtour/`) instead of only ever overwriting the root `js/content.js`. Each event folder is a full self-contained copy of the page set (`index.html`, `schedule.html`, `faq.html`, `survey.html`, `flight.html`, `location.html`, `upload.html`, `vote.html`) plus its own `content.js`, so the event keeps a permanent, shareable URL even after later events are deployed.
- Inside an event folder, shared assets are referenced two levels up (`../../css/style.css`, `../../js/main.js`, etc.) since the folder sits at `<org>/<event>/`; `content.js` itself stays local (`<script src="content.js">`, no `js/` prefix) since it's per-event, not shared. Because `content.js`'s own `heroImage`/`photo` paths are also resolved relative to the page that loads them, every `"images/..."` value inside an archived event's `content.js` must be rewritten to `"../../images/..."` (images themselves stay shared at the repo-root `images/` folder — they are not duplicated per event).
- `archive.html` (root-level, unlisted like `editor.html`) is a hand-maintained static directory of organizations (`<h2>` sections) and their events (cards linking to `<org-slug>/<event-slug>/`) — it does not auto-discover folders, so add a card here manually whenever a new event is archived.
- **Caution**: when scripting bulk edits to these files (e.g. filling in a title/og-tag from an event name), avoid `re.sub` with backreferences like `\1{value}\2` when `value` can start with digits — Python's `re` may consume a `\1` immediately followed by digits as an octal escape (e.g. `\120` → the single character `P`), silently corrupting the replacement and dropping the captured group. Use a replacement function (`re.sub(pattern, lambda m: m.group(1) + value + m.group(2), text)`) instead.
- The root `index.html`/`js/content.js` currently still serve whatever event was deployed most recently (unchanged legacy behavior) rather than the archive — flip root over to show `archive.html`'s listing only once the operator confirms the currently-live event's link is no longer being actively shared with participants, since that link should keep working until then.
